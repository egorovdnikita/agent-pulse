# Agent Pulse — паспорт проекта (рабочее название)

## Что это

Нативный macOS-виджет поверх всех окон, который показывает, что сейчас делает ИИ-агент (Claude, в том числе когда он работает с Figma), пока пользователь занят другим окном, Space или экраном. Агент визуализирован маскотом, который меняет состояние и анимацию по ходу работы.

Три оси ценности:

1. **Не пропустить момент, когда агент ждёт тебя.** Запрос разрешения или вопрос агента — главный сценарий потери времени: ты ушёл, агент стоит. Это ключевое событие продукта, важнее уведомления о завершении.
2. **Понимать прогресс без переключения окна.** Не лог, а 1–2 строки человеческого языка: «Создаёт 4 фрейма в Figma», «Читает переменные», «Запускает тесты».
3. **Видеть результат в Figma краем глаза.** Упрощённое живое зеркало окна Figma в компактной панели.

## Оценка реализуемости

Реализуемо, но не одинаково для всех источников. Граница проходит по тому, есть ли у источника наблюдаемый канал событий.

| Источник | Канал | Что видно | Статус |
|---|---|---|---|
| Claude Code (CLI, IDE, вкладка Code в Claude desktop) | Hooks → `pulse-hook` → сокет | Всё: запрос, каждый инструмент, разрешение, итог | **Готово** (MVP) |
| Claude Cowork | Хвост `~/Library/Application Support/Claude/local-agent-mode-sessions/**/audit.jsonl` (FSEvents) | Всё: `user` → запрос, `assistant.tool_use` → инструмент, `permission_request` → ждёт, `result` → итог (`is_error`) | **Сделано**. Формат внутренний (поток Agent SDK) → адаптер версионируется, при незнакомом формате молча выключается |
| Claude Chat: вызовы MCP (в т.ч. Figma-коннектор) | Строки `[MCP] tool_approval_gate` в `~/Library/Logs/Claude/claude.ai-web.log` (`toolName`, `approvalRequired`); локальные MCP — через MCP-прокси | Только вызовы инструментов и запрос одобрения | Под вопросом: лог неофициальный, пишется ли он сразу — не проверено |
| Claude Chat в браузере (claude.ai) | Расширение Chrome: content script следит за состоянием генерации (кнопка «Стоп», диалог одобрения) → native messaging → сокет | Генерирует / готово / ждёт одобрения | **Сделано** (`Extensions/Chrome`, мост — `pulse-hook` в режиме native messaging). Зависит от DOM claude.ai — селекторы изолированы в `content.js` |
| Claude Chat в Claude desktop | Публичного канала нет; ответы в логи не пишутся (проверено) | Только через Accessibility: кнопка «Stop response» в окне = генерация | **Сделано** как opt-in (`ChatWindowWatcher`), по умолчанию выключено. Подписи кнопок сверить по снимку окна |
| Встроенный ИИ Figma (AI в редакторе, First Draft) | Плагин-компаньон: `documentchange` | «В Figma меняется макет» + кадр зеркала. Авторство (ИИ или человек) не различить; эвристика — всплеск созданных нод (≥ 12 за 1.5 s) | **Сделано** (`FigmaCompanion`, HTTP на `localhost:47811`). Пороги не откалиброваны на реальной генерации. Плагин работает, только пока запущен в открытом файле |
| Figma Make | Отдельное веб-приложение, плагины в нём не работают | В браузере — через то же расширение Chrome (figma.com/make) | Только в браузере |
| Вызовы Figma MCP из локального клиента | Локальный MCP-прокси между клиентом и Figma MCP | Каждый вызов инструмента Figma | Реализуемо |
| Зеркало Figma | Плагин-компаньон: `nodechange` текущей страницы → `exportAsync` изменённого фрейма → localhost | Кадр изменённого фрейма; экспорт только пока агент рисует в Figma | **Сделано**. Работа на неактивном Space не проверена |
| Зеркало Figma (fallback) | Figma REST API `GET /v1/images` по id изменённых нод | Кадр с задержкой в секунды | Реализуемо, лимиты API |
| Захват окна Figma | ScreenCaptureKit | — | **Не подходит.** Окна на неактивном Space не захватываются |

Вывод: у каждого источника свой канал, но все сводятся к `AgentEvent`; маскот не знает, откуда событие. Глубина разная: Claude Code и Cowork видны полностью, Chat — только «генерирует / ждёт / готово», Figma AI — только «макет меняется». Маскот показывает то, что честно известно: без деталей инструмента — общий `work` или `think`.

Принципы для неофициальных каналов (Cowork-журнал, логи, DOM, Accessibility):
- Только чтение; никакого вмешательства в работу Claude и Figma.
- Читаем типы событий и имена инструментов, никогда — текст сообщений.
- Адаптер проверяет формат; незнакомый формат → источник помечается «недоступен» в меню, а не выдаёт ложные `done`/`error`.
- Каждый канал включается отдельно в настройках.

## Позиционирование

Голое уведомление «агент закончил» решается хуком и `osascript` за пять минут — на этом продукт не строится. Дифференциация:

- **Состояние «ждёт тебя»** как отдельный, громкий, но не раздражающий сигнал.
- **Человеческий перевод активности** вместо сырых имён инструментов, с агрегацией шума (20 чтений файлов = «Изучает проект»).
- **Маскот как интерфейс состояния**: состояние считывается периферийным зрением за долю секунды, без чтения текста.
- **Зеркало Figma**: видно, что агент рисует, не отрываясь от другой задачи.

### Единая модель события

Все источники приводятся к одному типу. UI и маскот ничего не знают об источниках.

```swift
struct AgentEvent: Codable, Sendable {
  let source: Source            // .claudeCode, .cowork, .claudeChat, .figmaMCP, .figmaCompanion
  let sessionId: String
  let kind: Kind                // .promptSubmitted, .toolStarted, .toolFinished,
                                // .awaitingUser, .subtaskDone, .stopped, .sessionEnded, .error
  let tool: String?
  let summary: String?          // уже очеловеченная строка, если источник её дал
  let context: String?          // проект / файл Figma
  let ts: Date
}

enum Phase {
  case idle, received, thinking, working(Activity),
       awaitingUser(reason: String), done(summary: String), failed(String)
}
```

### Маппинг Claude Code hooks

| Hook | Phase |
|---|---|
| `UserPromptSubmit` | `received` |
| `PreToolUse` | `working(tool)` |
| `PostToolUse` | возврат в `thinking` |
| `Notification` (запрос разрешения / простой) | `awaitingUser` — главный сигнал |
| `SubagentStop` | шаг таймлайна |
| `Stop` | `done` |
| `SessionEnd` | `idle` |

«Думает» не приходит событием — выводится `PhaseClock` из паузы после `received`/`toolFinished` без нового `toolStarted`. Ошибку `Stop` явно не сообщает: `failed` выставляется по ошибочному результату инструмента и по эвристике, не по догадке. Если уверенности нет — `done` с нейтральным маскотом.

`pulse-hook` обязан: отвечать < 50 ms, никогда не блокировать агента, при недоступном сокете молча выходить с `0`. Хук, который тормозит или ломает Claude Code, убивает продукт мгновенно.

### Маскот (MVP)

В MVP панель — это маскот и облачко-реплика рядом с ним. Маскот передаёт состояние, облачко — настроение момента в паре слов, системное уведомление — содержание. Подробности никогда не лезут в облачко.

#### Анатомия

Ровно три элемента, больше ничего: круглое тело с белым свечением и два глаза — сплошные чёрные вертикальные овалы (зрачок = весь глаз). Никаких ртов, бровей, век, цветовых акцентов. Вся выразительность — через пять параметров:

| Параметр | Диапазон | Что выражает |
|---|---|---|
| `gaze` (x, y) | −1…1 | куда смотрит; оба глаза двигаются вместе |
| `eyeScaleY` | 0…1.2 | моргание (0), прищур (0.6), удивление (1.2) |
| `eyeShape` | овал ↔ дуга «^» | счастье — только в `done` |
| `body` (offsetY, scale) | ±3 pt, 0.92…1.08 | подпрыгивание, сжатие, кивок |
| `glow` (radius, opacity) | — | дыхание, акцент |

Геометрия при диаметре 48 pt (всё масштабируется от диаметра): глаза 7×10 pt, центры на ±8 pt по X и −2 pt по Y от центра тела. Сдвиг глаз при взгляде: ±6 pt по X, ±4 pt по Y. При взгляде вбок дальний глаз сужается до 85% — даёт объём шара без лишних элементов.

Читаемость на фоне. Белое свечение исчезает на светлом холсте Figma и белых окнах. Поэтому под свечением всегда лежит мягкая тёмная тень (чёрный, 25%, blur 8). Это не четвёртый элемент: тень визуально считывается как часть свечения, но держит силуэт на любом фоне.

#### Базовое поведение (во всех бодрствующих состояниях)

- Моргание: закрытие 70 ms, открытие 110 ms. Интервал случайный 2.5–6 s, в 15% случаев двойное.
- Саккады: переход взгляда за 120–180 ms по spring без перелёта, затем фиксация. Длительность фиксации задаёт состояние.
- Взгляд и моргание связаны: при большой саккаде (> 0.6) в 30% случаев моргание в момент перевода — так делают живые глаза.
- Hover: при курсоре в радиусе 120 pt глаза следят за курсором; поверх `wait_you` hover не действует.

#### Состояния (лупы)

| Состояние | Phase | Поведение |
|---|---|---|
| `sleep` | нет активных сессий > 60 s | Глаза закрыты (`eyeScaleY` 0.08 — тонкие линии), свечение медленно дышит (период 5 s, opacity 40–60%). Ничего не двигается |
| `idle` | сессия есть, задач нет | Открытые глаза, редкие ленивые взгляды (фиксация 2–4 s), обычное моргание. Через 60 s — засыпает: глаза медленно закрываются за 1.2 s |
| `think` | пауза между действиями агента | Взгляд уходит вверх-в сторону (y −0.7, x ±0.5), фиксации 1.5–3 s, смена стороны. Лёгкий прищур 0.85. Свечение пульсирует медленнее |
| `work` | вызов инструмента | Смотрит по сторонам: частые саккады, фиксации 0.4–1.2 s, моргание чаще (интервал 2–4 s). Модус уточняется типом инструмента, см. ниже |
| `wait_you` | агент ждёт ввода или разрешения | Смотрит прямо на пользователя (gaze 0,0), глаза 1.15. Каждые 3 s: подпрыгивание на 3 pt + двойное моргание + вспышка свечения. Держится до реакции пользователя, не затухает |

#### Модусы `work` по типу инструмента

Модус меняет только паттерн взгляда — тело и свечение общие. Переключение плавное: текущая фиксация доигрывается.

| Модус | Инструменты | Паттерн взгляда |
|---|---|---|
| `read` | Read, Grep, Glob, Figma `get_*` | «Читает строки»: медленный проход слева направо (y фиксирован), быстрый возврат, y сдвигается на строку вниз |
| `edit` | Edit, Write, Figma запись (`use_figma` и т.п.) | Взгляд вниз (y +0.6), короткие сдвиги по X, прищур 0.75, моргание реже — сосредоточен |
| `run` | Bash, тесты, сборка | Следит за невидимой точкой: плавное ведение взгляда по дуге, иногда резкий переброс |
| `search` | WebSearch, WebFetch, субагенты | Взгляд далеко в стороны (x ±0.9), долгие фиксации, глаза 1.05 — высматривает |

Неизвестный инструмент → базовый `work`.

#### Реакции (one-shot, поверх состояния)

| Реакция | Триггер | Анимация | Затем |
|---|---|---|---|
| `notice` | новый запрос пользователя | Глаза распахиваются (1.2), взгляд на пользователя, подпрыгивание, двойное моргание. ~600 ms | `think` |
| `step` | завершён субагент / заметный шаг | Кивок: тело вниз на 2 pt и обратно, короткое моргание. ~300 ms | текущее |
| `done` | агент завершил | Глаза переходят в дуги «^ ^», тело подпрыгивает дважды, вспышка свечения. ~1.2 s | `idle`, глаза возвращаются в овалы через 3 s |
| `error` | сбой | Глаза сжимаются до 0.7, тело трясётся по X (±2 pt, 3 цикла), свечение гаснет до 40%. ~700 ms | `idle`, взгляд вниз 2 s |

Итого: 5 состояний, 4 модуса работы, 4 реакции, плюс hover-слежение.

#### Правила

- Приоритет при нескольких сессиях: `wait_you` > `error` > `done` > `work` > `think` > `idle` > `sleep`. Маскот один и показывает самую важную сессию.
- Реакции не прерывают друг друга, а встают в очередь; `wait_you` прерывает всё.
- Анти-дребезг: состояние держится минимум 400 ms, иначе быстрые события превращают маскота в тик.
- Reduce Motion: никаких саккад и подпрыгиваний; состояния передаются только формой глаз, направлением взгляда (статично) и свечением.
- Когда панель скрыта, `TimelineView` на паузе: ноль кадров, ноль CPU.
- Все числа живут в `MascotTuning` и крутятся в `MascotLab` вживую — финальная настройка движения делается глазами, а не в коде.

### Облачко-реплика

#### Форма

Маленький скруглённый пузырь с хвостиком к маскоту. Белая заливка, чёрный текст — та же палитра, что у маскота, та же мягкая тёмная тень для читаемости на светлом фоне. Шрифт SF Pro Rounded, 12 pt, medium. Высота 22 pt, горизонтальные отступы 8 pt, ширина по тексту.

Сторона — противоположная краю экрана, к которому прижата панель: маскот справа сверху — облачко слева от него. Облачко никогда не уходит за край экрана.

Появление: scale 0.6 → 1 от хвостика + fade, spring 180 ms. Уход: fade 200 ms. В момент появления маскот на 300 ms переводит взгляд на облачко, затем возвращается к своему паттерну — связывает реплику с персонажем. Reduce Motion — только fade.

#### Тон

Мягкий и человечный: так коллега бросает реплику через плечо, а не система пишет статус.

- Максимум 10 слов. Слово с дефисом («Так-так», «что-то») — одно слово; многоточие и знаки словами не считаются.
- Без восклицательных знаков, кроме редких случаев радости, без капса, без эмодзи.
- Без прошедшего времени с родом («понял», «сделал»): у маскота нет пола. Настоящее время, будущее и безличные формы — «беру», «готово», «не вышло».
- Без технических слов: никаких «Bash», «tool», «MCP», «запрос».
- На каждый триггер — пул из 3–4 вариантов, одна и та же реплика не повторяется дважды подряд.

#### Реплики

| Триггер | Реплики | Показ |
|---|---|---|
| `notice` (новый запрос) | Ага, беру · Берусь · Сейчас… · Так-так | 1.5 s |
| `think` | Хмм… · Думаю… · Секунду… · Прикину… | 2.5 s |
| `work.read` | Читаю… · Изучаю… · Смотрю… | 2.5 s |
| `work.edit` (код) | Пишу… · Правлю… · Собираю… | 2.5 s |
| `work.edit` (Figma) | Рисую… · Двигаю… · Леплю… | 2.5 s |
| `work.run` | Запускаю… · Проверяю… · Гоняю… | 2.5 s |
| `work.search` | Ищу… · Поищу… · Выясняю… | 2.5 s |
| `step` | Есть · Шаг есть · Дальше… | 1.2 s |
| `wait_you` (разрешение) | Можно? · Разрешишь? · Пустишь? | до реакции |
| `wait_you` (вопрос/ожидание) | Глянешь? · Жду тебя · Ты тут? | до реакции |
| `done` | Готово · Всё готово · Принимай · Вот, держи | 4 s |
| `error` | Упс… · Не вышло · Что-то не то | 4 s |
| засыпание | Вздремну | 1.5 s |
| hover в `sleep` | Привет · Я тут | пока hover |

#### Правила показа

- Одно облачко за раз. Очередь и приоритеты — те же, что у маскота; `wait_you` вытесняет всё.
- Реакции (`notice`, `step`, `done`, `error`, `wait_you`) показываются всегда.
- В `think` и `work` облачко — не чаще раза в 12 s и только если модус продержался ≥ 2 s. Иначе маскот превращается в болтуна, которого выключают.
- Минимальное время показа — 1 s, даже если состояние уже сменилось.
- Hover над маскотом показывает текущую реплику повторно; полный текст события — в уведомлении и в тултипе облачка через 1 s hover.
- Клик по облачку = клик по маскоту: переход к источнику.

Конфиг — JSON в Application Support, экспорт/импорт файлом.

```json
{
  "version": 1,
  "sources": { "claudeCode": true, "cowork": true, "claudeChat": false, "figmaMCP": true, "figmaAI": true, "figmaMirror": true },
  "display": {

    "anchor": "top-right",
    "screen": "active",
    "autoHideWhenSourceVisible": true,
    "expandOn": ["awaitingUser", "done"]
  },
  "events": {
    "awaitingUser": { "overlay": true, "notification": true, "sound": "soft" },
    "done":         { "overlay": true, "notification": true, "sound": "none" },
    "toolActivity": { "overlay": true, "notification": false }
  },
  "mirror": { "source": "companion", "fallback": "rest", "debounceMs": 800, "maxWidth": 320 },
  "mascot": { "skin": "default" },
  "privacy": { "showPromptText": false }
```

`autoHideWhenSourceVisible` — по умолчанию `true`: виджет прячет карточку источника, если окно этого источника сейчас видно на любом из мониторов. Проверяется видимость, а не фокус: при двух мониторах Figma может быть на втором экране без фокуса, и дублировать её незачем. Маскот при этом остаётся, если активен другой источник.

Клик по виджету активирует исходное приложение: терминал или IDE по bundle id, Figma по `figma://` URL файла. macOS сам переключит на Space с этим окном, если включено «При переключении на программу переходить в пространство с её окнами» (по умолчанию включено). Если выключено — показываем подсказку один раз.

## Spaces и мониторы

Рабочий сценарий: MacBook + внешний монитор, 4–6 Space, Figma и терминал/Claude живут на своих Space.

- Панель — `canJoinAllSpaces` + `fullScreenAuxiliary`: одна и та же панель видна на любом Space и поверх полноэкранных окон, без мигания при переключении.
- `screen: "active"` — монитор с курсором/ключевым окном, панель переезжает при смене. Альтернативы: `"main"`, `"builtin"`, конкретный монитор по UUID.
- Позиция хранится на монитор (анкер + отступ), а не в абсолютных координатах: при отключении внешнего экрана панель не уезжает за край.
- Источник никогда не определяется по положению окна на экране — только по событиям. Где лежит окно Figma, для статуса значения не имеет.

## Критические ограничения

### Производительность и ресурсы
- В простое CPU ~0%, RAM < 80 MB. Рендер маскота останавливается, когда панель скрыта; в `sleep` — не чаще 15 fps.
- Зеркало: кадр по событию, а не поток — экспорт после затихания изменений (~800 ms), даунскейл до ширины панели, в памяти только последний кадр.
- Агрегация обязательна: типовая задача Claude Code — десятки вызовов. В UI не больше одного обновления строки в ~700 ms.

### Права macOS
- Screen Recording не нужен: зеркало идёт от плагина/REST, видимость окон — через bounds без заголовков.
- Accessibility по умолчанию не запрашиваем. Исключение — opt-in наблюдение за чатом в Claude desktop (кнопка «Стоп»), включается пользователем отдельно.
- Для REST-fallback — Figma personal access token в Keychain.

### Установка хуков
- Изменение `~/.claude/settings.json` — только с явного согласия, с бэкапом и аккуратным мержем (не перезаписывать чужие хуки). Удаление — чистый откат.

### Приватность
- Ничего не уходит с машины. Текст промптов по умолчанию не показывается и не логируется.

## Валидация до кода

1. **Неделя на хуке + `osascript`.** Только уведомления `Notification` и `Stop`. Если поведение не меняется (не возвращаешься к агенту быстрее) — маскот этого не исправит, продукт под вопросом.
2. **Компаньон на неактивном Space.** Figma — Electron, а Chromium троттлит рендер и таймеры перекрытых окон. Проверить, что `documentchange` и `exportAsync` отрабатывают с приемлемой задержкой, пока Figma на другом Space. Если нет — основным становится REST-fallback.
3. **Маршрут Figma MCP:** проверить, идут ли вызовы из используемого клиента через локальный конфиг (проксируется) или через удалённый коннектор (не проксируется).
4. **Плагин-компаньон vs MCP:** может ли компаньон работать одновременно с записью в файл через MCP. Это главный риск зеркала.
5. **Шум:** записать события 10 реальных задач, проверить, что агрегатор сводит их к ≤ 7 строк таймлайна на задачу.
6. **Cowork в реальном времени:** пишется ли `audit.jsonl` по ходу работы (а не в конце), задержка от действия до строки.
7. **Чат и лог MCP:** появляется ли `tool_approval_gate` в `claude.ai-web.log` сразу при вызове инструмента.
8. **Figma AI:** отличим ли всплеск изменений от ИИ от ручной работы; срабатывает ли `documentchange` при генерации First Draft.

## Соглашения по коду

- Swift 6 strict concurrency. Состояние — `@MainActor` для UI, `actor` для `SessionStore`.
- Источники не знают про UI, UI не знает про источники — только `AgentEvent` и `Phase`.
- Новый источник = один адаптер + регистрация. Ядро не трогается.
- `Humanizer` — таблица правил с тестами: каждое правило проверено на реальном payload. Выдаёт два уровня: триггер для облачка (реплику выбирает `PhrasePicker`) и полный текст для уведомления.
- Лимит 10 слов проверяется тестом по всем репликам всех локалей. Реплика длиннее не собирается.
- `MascotStateMapper` — единственное место, где код знает о связи событий и анимации. Behaviors не знают про источники и инструменты.

## Definition of Done для источника

1. Адаптер нормализует payload в `AgentEvent` без потерь ключевых полей.
2. Тесты на записанных реальных payload: обычный, ошибочный, граничный.
3. Сбой источника не влияет на агента (хук/прокси прозрачны, таймауты).
4. Событие `awaitingUser` (если источник его умеет) доходит до уведомления < 1 s.
5. Неделя использования без ложных `done`/`error`.
